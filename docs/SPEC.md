## 1. システム全体の外部挙動

### 1.1 日次 podcast 生成フロー（MVP はモック）

```
[手動 text 入力]
  → 情報取得システム（テーマ情報テキストを出力）
  → テーマ原稿生成システム（テーマ原稿を出力）
  → 原稿生成システム（原稿.json を組立）
  → TTS システム（音声ファイルを生成・結合）
  → Drive 保存（エピソードとして保存）
```

- MVP では各ステップのロジックはモック（ダミーデータを返す）。
- end-to-end の連結が通ることだけを確認する。

### 1.2 オーケストレーションの起動

- 共通設定ファイルを読み込み、各システムへ設定を注入して起動する。
- 設定変更はコードを書き換えずに設定ファイルの編集で対応できる。
- cron 有効/無効を設定ファイルで制御できる（MVP では無効）。

## 2. 設定項目（オーケストレーションが管理）

| 設定項目 | 説明 | 初期値 |
|---------|------|--------|
| 尺 | 生成する podcast の長さ（5〜30 分） | 5 分 |
| 話者モード | `single`（1 人ニュース風）/ `dialogue`（2 人対話） | `single` |
| 情報源の有効/無効 | 情報取得システムごとに有効/無効を切り替え | 手動 text のみ有効 |
| 出力構成 | どの情報取得・原稿生成システムを使うか | 手動 text + デフォルト原稿生成 |
| テンプレート選択 | 番組構成テンプレートの選択キー | デフォルト |
| API provider | 原稿生成・TTS の provider 選択 | モック |
| Drive 保存先 | エピソードを保存する Drive フォルダ ID | 設定必須 |
| cron 有効/無効 | 定期実行の有効/無効 | 無効 |

## 3. 再生 UI

### 3.1 画面構成

- **エピソード一覧画面**: Drive 上の保存フォルダを走査し、エピソードを一覧表示する。
- **エピソード再生画面**: 音声プレーヤー + 原稿テキスト表示を同時に表示する。

### 3.2 操作

| 操作 | 動作 |
|------|------|
| エピソードをタップ | 再生画面へ遷移 |
| 音声プレーヤー | 再生・一時停止・シーク |
| 原稿テキストの単語をタップ | ポップアップに意味の検索結果を表示 |

### 3.3 認証

- 自分の Google アカウントでのログインを前提とする。
- public 公開しない。

## 4. 原稿.json 形式（MVP 仮置き）

```json
{
  "timestamp": "ISO8601形式",
  "body": {
    "opening": "最初のまとめテキスト",
    "topics": [
      {
        "title": "テーマタイトル",
        "script": "テーマ原稿テキスト"
      }
    ],
    "closing": "最後のまとめテキスト"
  }
}
```

## 5. MVP スコープ

| 項目 | MVP | 将来スコープ |
|------|-----|------------|
| 情報取得 | 手動 text モック | Twitter / Mastodon / IT ニュースフィード |
| 原稿生成 | モック | Claude API / Codex API |
| TTS | モック | gemini-flash |
| Drive 保存 | モック | 実 Drive API |

| 再生 UI | モック（一覧・再生・原稿・意味検索） | 実 Drive 走査・実音声 |

## 6. 成功の見え方（shim 向け確認ポイント）

1. `npm run orchestrate`（仮）を実行すると、モックのend-to-endが通りコンソールに完了ログが出る。
2. `npm run dev`（UI）を起動すると、モックエピソード一覧が表示され、タップで再生画面・意味検索ポップアップが動く。
3. 各システムの単体テストが `npm test` で全 pass する。
