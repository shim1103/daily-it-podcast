## 1. Decision

1. **concept**: 日常の IT 話題を扱う podcast だが、視聴体験の物語は「誰が聴いているか分からない／運営も不明／シェアの有無も不明なまま、ある日突然見つけた放送」とする
2. **setting**: 夜。正体不明の発見物としての放送空間。説明文や UI コピーで運営者・聴取者数・シェア状態を断言しない
3. **motif**: ミラーボール・夜・ヘッドホン・ホーン・ピアノは**物体として描かない**。色・艶・反射・暗がりといった質感の源としてだけ使う
4. 本 Decision の範囲は物語前提（何の空気か）まで。色値・semantic 階層・list 行の見え方の正は `2026-08-28T19-20-01-docs-playback-list-page-design` を正とする

## 2. Reason

1. shim が list-page の見た目指示で明示した設定は「運営不明・ある日突然見つけた」であり、product のトーンが再発する問いになる。session だけの雑談にすると次の agent が明るい公式 podcast の物語へ戻る
2. motif を絵や icon にすると、選択 UI が装飾で埋まり主用途を壊す。質感の源として固定すれば、視覚言語側は色と表面処理だけを決めれば足りる
3. 「日常 IT」の内容契約と、「謎の発見物」の体験トーンは両立する。前者は原稿・topic、後者は空気の判断基準になる
4. concept を CSS 値や参照 UI の構成で代替すると、物語の問いと視覚の問いが混線し DRY が壊れる。問いを分け、ここには物語だけを残す

## 3. Rejected

1. motif をミラーボールやヘッドホンのイラスト／絵文字で載せる — 物体化すると「質感」指示に反し、認識の主対象を装飾へ奪う
2. 運営者名・聴取者数・シェア UI を初期体験の前提として出す — setting の「不明」を断言で潰す。必要なら別契約で決める
3. 「明るい信頼できる公式チャンネル」を物語の既定にする — concept と逆方向
4. 本 file に色・typography・参照 list の構成合意を同居させる — 視覚言語の問いと混ざる。`2026-08-28T19-20-01` へ分離する
