## 1. Decision

1. 残す remote/local branch は、保護ブランチ（`master` / `develop`）と、いま進行中の未完了 work（active worktree 含む）だけにする。
2. 次は消す。release 済み、integration/base へ直接 merge 済み、直接は unmerged でも別経路で同趣旨が base に入ったもの、未 merge だが再開しないもの。
3. remote の feature branch 削除は「名前付き ref を外す」操作として扱い、到達可能な commit の正本は残る branch / tag / merge 先 / PR tip 参照に置く。GitHub の履歴表示を残置理由にしない。

## 2. Reason

1. 完了ラベルとしての remote feature branch は、`--merged` 判定や一覧ノイズを増やし、再開判断を曇らせる。
2. squash / 別 tip での再入では tip hash が base 祖先にならないが、機能の正本は base 側にある。tip を残す必要は薄い。
3. 未 merge かつ今後も触る tip だけは、唯一の簡単参照として残す（または削除前に tip SHA / tag を残す）。

## 3. Rejected

1. **merge 済みでも remote tip を保険で残す案** — 到達可能な履歴は base / PR から辿れる。残置は一覧と掃除コストだけ増やす。
2. **「GitHub は全履歴」だから未 merge tip も常に消してよい案** — PR 無し・他 ref 無しの tip は辿りにくく、recover を過信できない。進行中 work は残す。
3. **`--merged` だけを唯一の削除基準にする案** — 間接 merge（squash / 再実装）を取りこぼし、不要 tip が残る。
