## 1. Decision

1. 「全システムを固定レスポンスのモックで先に E2E 接続する」ことを、実装前の必須ゲートにしない。実境界（Drive・HTTP・secret・cron）に届かないモック結合を、受け入れの主証拠にしない。
2. 「原稿生成 / podcast 出力 / 再生 UI / 横断オーケストレーション」の 3 系統 + 中央 DI オーケストレーションを常設しない。ランタイムの正は `2026-08-15T16-23-06` の 2 系統。
3. 文書の常設形は再定義しない。正は `2026-08-15T16-23-08`（README・DESIGN・contracts。PROPOSAL / SPEC / QUESTIONS は置かない）。

## 2. Reason

1. code 前に系統数・MVP 定義まで固定した結果、後から系統数・UI 基盤・原稿経路がひっくり返った（archive rewrite）。
2. 要求の交差を解く作業と、未検証の構造を文書・モックで固定する作業は別である。後者を常設すると手戻りが前倒しされるだけで減らない。
3. 文書 3 分業と 2 系統は既に Decision がある。ここは初期ウォーターフォール側の手法だけを却下する。

## 3. Rejected

1. 実 API・実 Drive の前に全系モック E2E を必須にする案
2. 工程ごとの多系統 + 中央オーケストレーションを再び標準形にする案
3. PROPOSAL / SPEC / QUESTIONS を再び常設する案（`2026-08-15T16-23-08` と矛盾）
