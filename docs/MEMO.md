- private リポジトリ（GitHub 想定）。

## 2. 技術スタック（確定）

### 再生 UI 側
- フロント: Next.js / React / TypeScript
- インフラ: Vercel
- サーバーレス、DB なし（生成物は Google Drive に保存するため）

### システム側（podcast 出力・オーケストレーション）
- 実装技術は自由（UI 側スタックに縛られない）

## 3. 外部 API / サービス（将来の本実装対象。MVP では全てモック）

- 原稿生成: Claude API / Codex API（provider 差し替え可能な前提）
- TTS: gemini-flash
- 情報源: Twitter（非公式 API）・Mastodon（公式 API）・IT ニュースフィード
- ストレージ: Google Drive

## 4. 予算（確認済・PROPOSAL には数値非記載と決定）

- 予算は確認済みのため PROPOSAL に金額を固定記載しない。
- 参考（確認した実数）: gemini-flash TTS で 5min/日 ≒ 月数百円、30min/日 ≒ 月約2,000円規模。
- 尺は UI から 5〜30 分の範囲で変更可能にする。
- 実行時間は shim 側で調整するため、agent は無料枠の実行時間制約を考慮しなくてよい。

## 5. セッションで確定した補足事項

- 定期実行基盤と UI 基盤は別基盤に分離するが、同一 project 内の共通設定ファイルを参照する。
- cron 定期実行は deploy されるまで不要。実稼働は MVP スコープ外。
- 定常運用ループに Claude Code（対話 CLI）は入れない。無人実行は API で行う。Claude Code は初期構築時のみ関与。
- 「原稿そのまま読み上げ」= 原稿生成の確定出力 = 読み上げ対象 = UI 表示原稿、の三者一致（将来の本実装方針）。
- タイムスタンプはトピック単位の分割生成から算出し、1 エピソードは全トピック結合の 1 mp3 とする（将来の本実装方針）。
- 意味検索は「原稿内テキストをタップ → ポップアップに意味の検索結果」を指す（embedding ではなくこの挙動が初期目標）。
