## 重要な決定

**InfoFetcher: Hacker News 公式 API を採用**
IT Media News RSS との比較で、HN は無料・無認証・安定 REST API という利点があった。英語ソースだが、GeminiScriptGenerator が「日本語で原稿を書け」と prompt 指示するため品質問題なし。RSS parse ライブラリの依存追加なしで実装できた。取得件数はデフォルト 5 件で DI コンストラクタから設定可能にした。

**GeminiScriptGenerator: LLM に durationEstimateSec を決めさせる設計**
1〜3分・重要度・難しさで変えるという要件を、prompt 内で「60〜180 の整数を LLM が判断して JSON で返せ」と指示する方式にした。ルールベースで文字数から計算する方式と比較して、コンテンツの意味的重要度を考慮できる。prompt は `prompts/default.ts` に外出しし、実装クラスに触れずにスタイル変更できる。

**MeaningPopup: meaning ロジックを lib/meaning.ts に分離**
Route Handler と fetch ロジックを同一ファイルに書く選択肢もあったが、`lib/meaning.ts` に純粋関数 `fetchMeaning()` として分離することでテスト可能にした（Route Handler は Next.js ランタイム依存でテストが困難）。cancelled フラグで word 変化時の古いレスポンス上書きを防止した。

**conflict 解決方針**
PR #4（HN fetcher）と PR #5（Gemini generator）が両方とも `di.ts` を編集していたため CONFLICTING。両ブランチの DI 分岐を統合して解決。pnpm-lock.yaml は develop 側を base に `pnpm install` で再生成した。
