ESLint merge 後、develop の `pnpm-lock.yaml` が変わったため PR#8 の rebase が失敗。worktree 内で `git rebase origin/develop`、conflict 時に `checkout --theirs`（develop 版を優先）して続行。
- **代替案**: squash-merge で flat history にする（ただし git bisect が困難）。
- **判断**: `--theirs` で conflict 解決して rebase 続行が最小コスト。`pnpm-lock.yaml` は再生成ファイルなので develop 版を信頼できる。

### TDD サイクルの厳守
全 3 PR とも Red → Green → （Refactor）の順序を明確に commit で分離。
- Red commit: テストファイル先行、実装なし（intentional failure）
- Green commit: 最小限の実装で PASS
- Refactor commit: （ESLint/tailwind は code cleanup で含まれた）

この構造により conflict 時の blame が明確で、どの commit の影響か追跡可能になった。
