#### 実装ポイント
- **Interface設計**: InfoFetcher / ScriptGenerator / ManuscriptBuilder / TtsService / DriveService の5個のinterfaceで境界を分離
- **DI**: Orchestratorがconfig経由で各systemにinterfaceをinject、テスト・API provider変更時の差し替えが容易
- **モック**: 各systemが固定レスポンス返却。end-to-endフローの連結確認が目的
- **テスト**: Vitest。Given-When-Then記法。各システム境界 + end-to-endで観点網羅。計10テストall pass
- **UI**: React Server Components + `use client` で境界分離。モックDriveServiceを静的importで引き出し、ファイルI/Oなし
