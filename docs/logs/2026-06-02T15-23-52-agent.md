## 重要な決定

**TDD規約の厳密運用**
TDD（test → impl）の順をコミット単位で分離。各パッケージ（TTS・Drive・Orchestrator）で `test: xxx` → `feat: xxx` の2コミット構成に統一。red・green・refactorを明示的に保証し、実装の正確性とコードレビュー時の追跡可能性を両立。

**DI切り替えを純粋関数に隔離**
Orchestrator パッケージに `createDeps(config)` を独立させ、テスト可能・再利用可能にした。main.ts が単純化され、設定値の変更だけで実装を切り替える直交性を確保。

**環境変数の有無で Web UI も自動選択**
Google Drive 認証情報が揃っているかで自動判定。本実装時にコード変更なしに GoogleDriveService に移行可能。運用上、環境変数の有無 = 機能の有効化・無効化という UNIX哲学に合致。

**並列実装ではなく直列化による完全性**
4つの feature ブランチ（tts → drive → orchestrator-di → web）を直列に積み重ね、依存関係を明確化。各完成度を高めてから次へ進む戦略。結果として「全パッケージテスト・typecheck パス」を実現。

## 完了した作業

1. **TTS本実装** (`packages/tts/src/gemini-tts.ts`)
   - Gemini SDK `@google/genai` を使った `gemini-2.5-flash-preview-tts` モデルでの合成
   - `buildScript()` で原稿を構造化テキストに変換
   - `synthesize()` でレスポンスの base64 をデコードして Buffer 返却
   - 5テスト（失敗系含む）で API エラー・空ペイロードをカバー

2. **Drive本実装** (`packages/drive/src/google-drive.ts`)
   - googleapis `v3` API + OAuth2 リフレッシュトークン方式
   - `save()` で音声ファイル + JSON メタデータ（appProperties）をアップロード
   - `listEpisodes()`・`getEpisode()` で Drive の webContentLink を audioUrl として返却
   - 4つのファイル操作をモック化して 5 テストで動作確認

3. **Orchestrator DI** (`packages/orchestrator/src/di.ts`)
   - `config.apiProvider.tts` / `.drive` に基づきて Mock/本実装を自動選択
   - `createDeps(config)` が純粋関数として testable
   - DI テスト 4つで両パターン（mock・本実装）を検証

4. **Web UI 接続** (`apps/web/src/lib/drive.ts`)
   - 環境変数チェック → GoogleDriveService | MockDriveService を自動選択
   - 既存の async page component（page.tsx・[id]/page.tsx）は変更不要

5. **config 型拡張** (`packages/core/src/config.ts`)
   - `PodcastConfig.apiProvider.drive?: 'mock' | 'google'` を追加
   - オプショナルで後方互換性を保証
